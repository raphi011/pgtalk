# The four questions on a real plan

<Plan
  analyze
  appearAt={1}
  focus={[
    { at: 2, until: 3, node: "Seq Scan" },
    { at: 3, until: 4, metric: "rows" },
    { at: 4, until: 5, metric: "loops" },
    { at: 5, metric: "buffers" },
  ]}
  sql={`SELECT c.country, count(*)
FROM customers c JOIN orders o ON o.customer_id = c.id
WHERE o.total_cents > 200000
GROUP BY c.country;`}
/>

<Note appearAt={2} hideAt={3}>

**1 · Innermost first.** The two scans at the bottom are the only nodes that
touch a table. Read upwards as one sentence: scan both, hash `customers`, join,
count per country.

</Note>

<Note appearAt={3} hideAt={4}>

**2 · Estimate against actual.** Every node is within a few percent.
`total_cents` has an ordinary histogram, so the planner read the filter's
selectivity straight off it. This plan was decided correctly.

</Note>

<Note appearAt={4} hideAt={5}>

**3 · Loops.** Every node ran once, so every time is already a total. Check
it anyway, every time, including when the answer is 1.

</Note>

<Note appearAt={5}>

**4 · Buffers.** `hit` came from shared buffers; `read` came from outside
them. Run it again and the reads turn into hits: same tree, a different
clock.

</Note>
