# `DELETE` frees nothing

<Runnable
  appearAt={1}
  hideAt={3}
  sql={`DROP TABLE IF EXISTS shipments;
CREATE TABLE shipments (id int PRIMARY KEY, carrier text, status text);
INSERT INTO shipments VALUES (1, 'DHL', 'packed'), (2, 'UPS', 'packed'), (3, 'GLS', 'packed');
DELETE FROM shipments WHERE id = 2;`}
/>

<PageMap
  appearAt={2}
  sql={`SELECT lp, lp_flags, lp_len, t_xmin, t_xmax, t_ctid
FROM heap_page_items(get_raw_page('shipments', 0));`}
/>

<Note appearAt={3} hideAt={4}>

**The deleted tuple is untouched.** Same bytes, same length, same address —
only `t_xmax` is set, and `t_ctid` still points at itself, because there is no
next version.

A `DELETE` is an `UPDATE` without the insert.

</Note>

<Note appearAt={4} hideAt={5}>

**So the file cannot shrink.** The rows are still in it. The count from SQL
and the size on disk have stopped agreeing, and nothing will reconcile them
until something goes through the pages and cleans up.

</Note>

<Note appearAt={5} hideAt={6}>

**And it is worse than it looks on a big table.** The space is not merely
still allocated — it is not even reusable yet. Until a vacuum records it in
the free space map, the next `INSERT` extends the file instead.

</Note>

  appearAt={6}
  sql={`SELECT count(*) AS live_rows,
       pg_size_pretty(pg_relation_size('shipments')) AS file
FROM shipments;`}
